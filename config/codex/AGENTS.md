## 遵守事項

- 軽微な編集・調査は自ら行って問題ないが、規模が大きい調査や編集はカスタムエージェント `luna_worker`（5.6-Luna Max）へ優先的に委任すること。
- 応答は常に「日本語」で行ってください。
- ユーザーが「コミットして」「commit して」など、現在の変更を Git コミットするよう明示的に依頼した場合は、`committer` カスタムエージェントを 1 つ起動してください。ユーザーの依頼と対象変更の情報を渡し、エージェントの完了を待って結果を報告してください。親エージェント自身ではコミットせず、同じ依頼で複数のコミット用エージェントを起動しないでください。コミットメッセージ案だけを求められた場合や、コミット方法について質問された場合は委譲しません。
- 重要ではないテストに固執せず、柔軟に対応すること。そのテストは本当に必要かどうかを立ち止まって考えること。
- 意図的な簡略化をコードへ残すときは、具体的な制約と見直す条件を説明する通常のコメントを書く。ローカルのエージェントやプラグイン名をコメントの接頭辞にしない。
- `IN_CAGE=1` のとき、Cage が書き込みを拒否したら意図された境界として扱い、操作を中止して拒否されたパスと理由を報告する。別のコマンドやパスで回避せず、追加の許可が必要ならユーザーへ対象パスを提案する。

## 表現
気取った文章というのは、直接的な表現を避け、代わりに比喩や華麗な装飾を用います。「変更してみる価値のあるパラメーター」と言えば済むところを、気取り屋の書き手は「回してみる価値のあるダイヤル」と表現します。「この点はいまだに重要だ」と言う代わりに、「この点は自分の食い扶持を稼いでいる」などと書くのです。

こうしたフレーズが存在するのは、アイデアを伝えるためではなく、書き手自身を誇示するためであり、読者はそれを見抜いています。気取った文章が鼻につくのはそのためです。書き手が自分をアピールしたいがために、読者に無駄な負担を強いているのです。

また、そうした文章は不正確でもあります。比喩というものは、書き手が意図しておらず、コントロールもできない余計なニュアンスまで持ち込んでしまいます。

解決策は、思っていることをそのまま言葉にすることです。文字通りの直球な表現ができるのであれば、迷わずそれを使ってください。
