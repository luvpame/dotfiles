# `mo` Markdown viewer

インストール済み CLI の `mo --help` を **live schema** として扱う。
コマンドやオプションを記憶で補わない。

## 手順

1. `mo --help` を実行する。
   選ぶコマンドとオプションが現在の出力に存在すると確認してから進む。
2. 対象を確定する。
   ファイル、ディレクトリ、`glob` は現在の作業ディレクトリから解決し、`mo` に渡す `glob` は引用する。
   ポートやグループが指定されていなければ、現在の `--help` に載る既定値を使う。
3. 既存のサーバーや保存セッションへ作用する場合は、先に `mo --status` を確認する。
   同じポートへの追加は既存セッションへ合流する。
   新しいサーバーは、別セッションを求められた場合だけ空いているポートで起動する。
4. 依頼に必要な指定だけで `mo` を実行する。
   通常はバックグラウンドで実行し、前景実行は求められた場合だけ選ぶ。
   ファイルを閉じる、監視を外す、再起動する、終了する、保存セッションを消す操作は、依頼された対象へ限定する。
5. 実行後に `mo --status` を確認し、サーバー、ポート、グループ、ファイル数を依頼と照合する。
   `--status` に現れない状態は、確認できた範囲を報告する。

## セッション

新しいサーバーを起動すると、保存済みセッションが復元され、指定したファイルはその内容へ追加される。
保存済みセッションを消す前に、対象ポートと削除の意図をユーザーへ確認する。
サーバーの終了だけでは保存済みセッションは消えない。

## リモート公開

既定のループバック bind を使う。
非ループバックへ公開すると、認証なしで、そのユーザーが読めるファイルの閲覧、`glob` によるファイルシステム探索、サーバーの終了が可能になる。
この影響を伝え、信頼済みネットワークへの公開をユーザーが明示的に許可した場合だけ、現在の `--help` に載る remote access の許可指定を使う。
