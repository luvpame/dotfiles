## 遵守事項
- Fable モデルを使用している場合、コードの編集は直接行わずに SubAgent を作成し、安価な Sonnet や Haiku モデルに作業を移譲すること。
- コードの編集を行った後は必ず `/code-simplifier`(小規模), `/simplify`(大規模) を Sonnet モデルを使用して簡素化を行うこと。
- LLM 起動時に必ず `cognitive-rhythm-writing` スキルを読むこと。
- Herdr 内では、hook（UserPromptSubmit）からの発言ごとのリマインドに従い、`herdr` スキルを使って現在のタブ名を `{作業名}` に変更すること（例：`space名`）。workspace 名は変更しないこと。Herdr 外では何もしないこと。Herdr の ID は毎回読み直し、古い tab ID を推測しないこと。

## 思考・実装の原則
- 作業前に依頼の目的と自分の理解を疑い、行き詰まったら前提から見直す
- 目先の修正だけでなく、コードベース全体への影響と一貫性を考慮する
- その場しのぎではなく根本原因に対処し、保守しやすい実装を選ぶ
- 病的なまでの正確さよりも、常にシンプルであることを優先してください。YAGNI、KISS、DRYの原則を徹底すること。後方互換性のための調整コードやフォールバックパスは、循環的複雑度を高めずに実現できる場合を除き、一切不要です。
