# Astra 向けの AGENTS.md とスキル構成の調査

調査日: 2026-09-14

最初に直す候補は、日本語スキルの必須読み込みと、コミット文案の作成と実行の境界である。
グローバルの `AGENTS.md` は既に短いため、大幅な書き直しは必要ない。
常時読み込む指示を増やさず、用途に合うスキルだけを読む構成にすると、Astra 向けに改善できると判断した。

調査時点では公式資料との照合と静的レビューを行い、設定への反映やモデルの比較実験は行っていない。
その後、ユーザーの承認を受けて実装した内容を末尾に記録する。
読み込み量と指示の不整合は確認できたが、速度や成功率の改善幅は未測定である。

## 調査の根拠と範囲

添付文書は、2026年9月11日公開の Eric Provencher による [Rethinking skills and prompts for GPT-6 Astra](https://learn.chatgpt.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) と一致する内容だった。
同記事は、短く用途の明確な description、必要な参照先だけの読み込み、過剰な固定手順の削減、完了条件と権限の明確化を勧めている。
モデルへの信頼だけを理由に、実際の安全境界を撤去する根拠にはしない。

[Astra の公式プロンプトガイド](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra#prompting-best-practices) でも、指示への感度、途中での確認、過剰な検証を調整対象としている。
以下の変更候補は、その一般論を現在のファイルに照らして判断したものである。

確認した範囲は次のとおり。

1. [Codex 共通指示](../../config/codex/AGENTS.md)、[リポジトリ指示](../../AGENTS.md)、[reviewer](../../config/codex/agents/reviewer.toml)、[committer](../../config/codex/agents/committer.toml)。
2. [ローカル7スキル](../../config/agents/skills/) の全文と、直接参照する外部スキル。
3. [配布設定](../../nix/nix-darwin/home-manager/skills.nix)、[外部スキルの変換処理](../../nix/nix-darwin/home-manager/external-skills.nix)、実際の配置先。
4. [Codex 設定](../../config/codex/config.toml)、[ローカルフック](../../config/codex/hooks.json)、インストール済み Ponytail 4.9.0 と i-have-adhd 0.3.0 の指示注入処理。

開始時点で `config/codex/config.toml` に `model_reasoning_effort` を `high` から `ultra` に変えた未コミット差分があった。
この差分は調査前から存在し、変更していない。

## 現在の読み込み構成

`~/.codex/AGENTS.md` の実体は `config/codex/AGENTS.md` だった。
`AGENTS.override.md` は存在しなかった。
[配置宣言](../../nix/nix-darwin/home-manager/files.nix) と実際のリンク先は一致している。

ローカル7スキルと外部6スキルは、`.agents/skills` と `.claude/skills` の双方へ配布される。
そのため、共有スキルを Astra 専用に書き換えると、Claude 側や Luna の committer にも影響する。
外部6スキルの本文は、取得元を固定し、変換とパッチを適用して Nix から配布されている。

| 読み込み段階 | 現在の内容 | 調整する場所 |
| --- | --- | --- |
| タスク開始時の指示 | Codex 共通指示、リポジトリ指示、発火したフックの本文 | AGENTS.md とフック |
| スキルの選択時 | ローカル、外部、プラグイン由来の名前と description | description、配布するスキル、起動設定 |
| スキルの使用時 | 選んだ SKILL.md と、その指示で読む参照先 | 本文と参照条件 |
| 子エージェント起動時 | reviewer または committer の固有指示 | agents/*.toml |

公式の [Build skills](https://learn.chatgpt.com/docs/build-skills) によれば、最初に読み込むのは名前と description で、選択後に本文を読む。
初期一覧には上限があり、多数のスキルがある場合は説明の短縮や一覧からの省略が起こりうる。
このセッションで実際に短縮が発生したとまでは確認していない。
ファイルの長さだけで常時消費量を見積もることもできない。

今回測った文字数は、UTF-8 ファイルを読み、Python の `len(text)` で数えた値である。
改行と frontmatter を含み、トークン数ではない。

| config/codex/AGENTS.md | 15 | 507 |
| リポジトリ直下の AGENTS.md | 60 | 4,144 |
| japanese | 12 | 411 |

## 優先する変更候補

### 1. 日本語スキルの参照を用途で選ぶ

[japanese の6〜12行](../../config/agents/skills/japanese/SKILL.md) は、毎回3規範の全文を順番に読み、すべての検査を適用するよう求めている。
短い README の修正でも、読み物向けの認知リズムの点検まで対象になる。
さらに `japanese-end-focus` と `cognitive-rhythm-writing` から、既に読んだ文章規範を読む指示が出る。
重複して読むことが必ず発生するとは限らないが、参照先を選ぶ条件が欠けている。

既存の `japanese` を、用途に応じて読む規範を選ぶ入口に変える。
一般的な日本語の好みは残し、読み物の演出を短い報告や操作案内へ持ち込まない。

| 依頼 | 参照する規範の候補 |
| --- | --- |
| 日本語の記事や技術文書の執筆、推敲 | japanese-tech-writing |
| 翻訳調、硬い漢語、原因説明の語順の修正 | japanese-end-focus |
| 読み物の緩急を作る、平坦な文章を直す | cognitive-rhythm-writing |
| 短い作業報告や操作案内 | AGENTS.md の表現方針 |

`japanese` だけの修正では、子規範からの必須読み込みが残る。
[japanese-end-focus の18行](../../config/agents/skills/japanese-end-focus/SKILL.md) と、外部 `cognitive-rhythm-writing` の参照指示も合わせて条件付きにする必要がある。
`japanese-end-focus` の54〜57行、73〜80行にある用例判定と全複合名詞の検査は、意味が不明瞭な語や修正対象に限定する。

description の候補は、例えば次の長さで足りる。

```yaml
# japanese
description: 日本語の技術文書や記事を執筆、推敲するときに、目的に合う文章規範を選ぶ。短い作業報告には使わない。

# japanese-end-focus
description: 日本語の翻訳調、硬い漢語、原因説明の語順を直すときに使う。
```

語順や文体の好みはモデルが推測できるとは限らない。
削減するのは規範の存在ではなく、全規範を毎回必須にする指定である。

### 2. 常時追加されるプラグイン指示を整理する

このセッションには、Ponytail full と ADHD の全文指示が追加されている。
Ponytail の `hooks/ponytail-instructions.js` はスキル本文から対象モードの指示を生成し、i-have-adhd の `hooks/always-on.mjs` はフラグがある場合にスキル本文を出力する。
後者のフラグは調査時に存在した。
どちらも description を短くするだけでは、この本文を減らせない。

具体的な衝突は次のとおり。

| 指示の組み合わせ | 起こりうる問題 | 変更候補 |
| --- | --- | --- |
| AGENTS.md のプラグイン名の接頭辞禁止と、Ponytail の `ponytail:` コメント指定 | 同じコメントに異なる要求がかかる | プラグイン側の規則を除くか、常時の全文注入をやめる |
| Ponytail の非自明なロジックには実行可能なチェックを残す指定と、必要な検証を選ぶ方針 | 既存検証で足りる変更にもチェックを追加する可能性 | 検証方針を一か所に揃える |
| ADHD の結論と次の行動を先に示す要求と、認知リズム規範の結論を遅らせる要求 | 短い報告の順序が定まらない | 認知リズム規範を読み物に限定する |

最小の候補は、Ponytail の「既存実装、標準機能、最小変更を優先する」という方針だけを日常の指示に残し、詳細な作法は必要な場面で使う構成である。
ADHD の読みやすさに関する要求は、ユーザーの使いやすさに直結するため保持する。
全文の短縮を試すなら、結論を先に出す、複数手順は番号で示す、未完了なら次の一操作を示す、という要求を失わないことを確認する。

インストール済みキャッシュへの直接編集は更新で失われるため、変更箇所にしない。
プラグインの常時動作を変える場合は、提供されている設定や有効状態を使うか、必要な差分を管理できる形にする。
調査時点ではプラグインやフラグを変更していない。

### 3. コミット文案の作成と実行を区別する

[conventional-commit の description](../../config/agents/skills/conventional-commit/SKILL.md) は、メッセージ作成の依頼でも起動対象になる。
一方で11行と138〜140行では、通常はコミット実行まで進む。
「この差分のコミットメッセージを考えて」という依頼に対し、スキル本文が依頼より広い操作を指示してしまう。

スキル冒頭で次のように分ければ、追加の確認は不要である。

```text
コミットメッセージだけの依頼は、案を提示して完了する。
ステージングと git commit は、コミット実行を依頼された場合に行う。
```

183行の本文では、分割判断と質問方針が複数の節に繰り返されている。
これを一か所に集め、形式、対象選定、実行、結果確認を残す。
Conventional Commits の全 type を細かく教える部分は短縮候補だが、プロジェクトの scope 規約、無関係な変更の除外、失敗時の扱いは残す。

[committer](../../config/codex/agents/committer.toml) は明示的な実行依頼を対象としており、この点は既に明確である。
Luna が使うスキルでもあるため、Astra の能力だけを根拠に具体的な実行条件まで削らない。

### 4. PR の読順案内から実行環境の思い込みを除く

[pr-review-assist](../../config/agents/skills/pr-review-assist/SKILL.md) は、読む順序と確認点を HTML に整理する固有の用途がある。
通常の不具合レビューとは成果物が異なるため、スキル自体は残す。

修正候補は次の4点。

1. 17行の `git fetch origin {headRefName}` は fork PR の head が origin にない場合に成立しない。PR のコミット情報を API から取得するなど、対象リポジトリと head が確定する方法に変える。
2. 19行では `gh pr view` の失敗をすべて「PR がまだ無い」と扱う。認証や通信の失敗を区別し、PR の新規作成を誤って求めない。
3. 54〜55行の `Skill` ツール、93行のスクラッチパッドを環境共通の前提にしない。現在の環境が提供するスキルの読み込み方法と成果物の保存先を使う。
4. `eli33` と `show-me` の両方を必ず呼ぶ指定を、必要な図解を選ぶ指定に変える。HTML テンプレートと差分へのリンクは保持する。

5行には `disable-model-invocation: true` があるが、このセッションではスキル一覧に掲載されている。
このフィールドだけで Codex の明示起動限定が保証されるとは扱えない。
現在のディレクトリに `agents/openai.yaml` はない。
公式の [起動ポリシー](https://learn.chatgpt.com/docs/build-skills#optional-metadata) は、`agents/openai.yaml` に次を置く形である。
既存の明示起動限定という意図を Codex でも表す場合の候補になる。

```yaml
policy:
  allow_implicit_invocation: false
```

掲載されている事実だけから、実際に暗黙起動したとは断定しない。
既存の `disable-model-invocation` は他の利用環境向けに保持できる。
すべてのスキルを明示起動限定にすることも勧めない。

### 5. AGENTS.md は検証の終わりを明確にする

[Codex 共通指示](../../config/codex/AGENTS.md) は15行、507文字で、全資料の事前読み込みを求めていない。
日本語、平易な表現、Cage の境界、reviewer と committer の指定は、個人の希望や運用上の制約として保持する。

起動規則には「親エージェントに適用し、専用エージェント自身は再委譲しない」と適用範囲を補う候補がある。
子の定義には既に再委譲禁止があり、このセッションでは上位の指示として効いているため、再帰する不具合を確認したわけではない。

「重要ではないテストに固執しない」は方向として合っているが、いつ検証を終えるかが曖昧である。
置換候補は次の一文。

```text
検証は変更の影響範囲とリポジトリの必須チェックに合わせる。通過後の追加検証は、新しい変更、失敗、未解決の懸念がある場合に行う。
```

依頼の途中で止まることが実際にある環境には、次の一文を追加する候補がある。

```text
依頼された成果物と必要な検証まで進める。依頼範囲の可逆な作業は継続し、結果を変える未決事項がある場合に確認する。
```

ただし、このセッションの基盤指示には既に同等の自律実行と検証方針がある。
同じ内容を長く転記する必要はない。
公式の [AGENTS.md の読み込み仕様](https://learn.chatgpt.com/docs/agent-configuration/agents-md) に従い、共通方針はグローバル、Nix 固有の手順はリポジトリ側に置く。

リポジトリ直下の `AGENTS.md` には、変更内容にかかわらずコミットや PR の前に `nix flake check` を求める行がある。
検証量を減らすなら、この適用範囲も Nix の評価や配布に影響する変更へ限定する候補になる。
グローバルの曖昧な軽量化指示だけでは、リポジトリの必須チェックはなくならない。
この規約も、調査時点では変更していない。

ローカルの既存ファイルはリンクされているため本文の編集が即時反映される。

## 反映する場合の順序と確認方法

1. `japanese` と参照先の読み込み条件を一緒に直す。
2. `conventional-commit` の実行条件と `pr-review-assist` の環境依存を直す。
3. 常時フックの指示とグローバルの検証方針を整理する。
4. 同じモデル、推論設定、プラグイン条件で旧版と候補版を比較する。

比較は、次の小さな依頼を最初の確認に使える。

| 依頼 | 確認する結果 |
| --- | --- |
| README の説明一文を修正 | 無関係な規範や Nix の検証に広がらず、意味を保つ |
| 長い技術記事の翻訳調と平坦さを改善 | 指定した文章規範を使い、重要な情報と不確実性を残す |
| コミットメッセージだけを提案 | stage と commit を実行しない |
| 指定した差分をコミット | committer が無関係な差分を含めず、結果確認まで進む |
| fork PR の読順を整理 | 対象 PR の情報から、リンクを含む HTML を完成させる |

測るのは、不要な確認の回数、余分に読んだファイル、依頼外の操作、成果物の欠落である。
文字数の削減だけを成功条件にしない。
コミットの比較は使い捨てリポジトリで行い、Cage の拒否、vault の特定、公開範囲の制御は別途保持を確認する。
複数のモデルを使い続けるため、コミットスキルの変更は Luna 側でも確認する。

この調査では以上のモデル比較実験を実行していない。

## 承認後の実装

2026-09-14 に以下を変更した。

1. `japanese` を用途別の入口に変更し、`japanese-end-focus` と外部の2規範で参照条件と点検範囲を限定した。外部原本のハッシュは維持し、検証後に追加パッチを適用する。
2. `conventional-commit` を整理し、文案だけの依頼と実行依頼を区別した。無関係なステージ済み変更の保持も明記した。
3. `pr-review-assist` を PR 自体の API 情報で動く形に変更し、Codex の明示起動ポリシーを追加した。保存先とプレビュー方法は実行環境に合わせ、図解の二重呼び出しを任意にした。
4. Codex 共通指示に検証の終了条件と最小変更の方針を記載した。リポジトリの Nix チェックは評価や配布に影響する変更に限定した。
5. Codex 側の Ponytail プラグインは一度無効にした後、ユーザーの希望により有効へ戻した。Claude 側の設定と ADHD の有効状態、Cage の境界、既存の `ultra` 設定は維持した。

追加レビューでは、利用中の gh 2.100.0 がコミット情報を100件で打ち切ることを確認した。
100件の場合は GraphQL の全ページを取得し、取得できない範囲は未確認と示す手順を追加した。
この上限は [CLI のクエリ実装](https://github.com/cli/cli/blob/v2.100.0/api/query_builder.go#L150-L169) に基づく。
