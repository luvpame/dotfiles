# cclens Nix 導入実装計画

**Goal:** cclens の CLI と Claude Code plugin を仕事用プロファイルへ導入し、日常の `just us` で両方を同じ upstream revision へ更新する。

**Architecture:** `lambdalisue/cclens` の default branch を Flake input として追跡する。CLI は upstream の `packages.${system}.default` を使い、plugin は同じ input 内の `plugins/cclens` を Claude Code の `--plugin-dir` へ渡す。`claude` wrapper がこの引数を毎回付けるため、marketplace の別管理を挟まず CLI と plugin の revision を一致させる。

**Tech Stack:** Nix Flakes、nix-darwin、Home Manager、Claude Code `--plugin-dir`

**調査結果:** [cclens Nix 導入調査](../../research/cclens-nix-2026-08-06.md)

## 更新方針

`inputs.cclens.url` はタグで固定せず、`github:lambdalisue/cclens` とする。
通常時は `flake.lock` が取得済み revision を固定し、`just us` が実行する `nix flake update` で default branch の新しい revision を取り込む。
続く `nh darwin switch` が CLI package と plugin directory を同じ generation へ反映する。

この方式は「最新リリースタグ」ではなく upstream の default branch を追跡する。
リリースだけに限定しながら `nix flake update` だけで自動追従する仕組みを upstream は提供していないためである。

## 変更するファイル

- Modify: `nix/flake.nix`
- Modify: `nix/flake.lock`
- Modify: `nix/nix-darwin/nix-core.nix`
- Modify: `nix/nix-darwin/home-manager/packages/work.nix`

`justfile` は変更しない。
既存の `update-and-switch: update switch` が cclens も更新する。
`config/claude/settings.json` も変更せず、plugin marketplace の更新状態と競合させない。

## Task 1: cclens を Flake input に追加する

**Files:**

- Modify: `nix/flake.nix`
- Modify: `nix/flake.lock`

- [ ] `inputs.cclens.url = "github:lambdalisue/cclens"` を追加する。
- [ ] cclens 独自の lock graph を維持し、`inputs.nixpkgs.follows = "nixpkgs"` は設定しない。
- [ ] `nix flake update cclens --flake path:./nix` で input と依存 node を `flake.lock` に記録する。

cclens の `nixpkgs` をこのリポジトリへ追従させると upstream Cachix の derivation と一致しなくなる可能性がある。
更新時のローカル Rust build を避けやすくするため、upstream が検証した lock graph をそのまま使う。

## Task 2: upstream Cachix を Nix daemon に追加する

**Files:**

- Modify: `nix/nix-darwin/nix-core.nix`

- [ ] `extra-substituters` に `https://cclens.cachix.org` を追加する。
- [ ] `extra-trusted-public-keys` に upstream 公開鍵を追加する。

  ```text
  cclens.cachix.org-1:0QUNU6PuVyf+yXOvg3n1rd3FksBoB3s3/Jty50iKRNQ=
  ```

- [ ] 既存の `ryoppippi.cachix.org` とその鍵を維持する。

この公開鍵を信頼すると、cclens Cachix が署名した Nix store path を受け入れる。
初回 switch では現行 daemon に設定がまだ入っていないため、ローカル build が発生する可能性がある。
一度反映した後の `just us` は binary cache を利用できる。

## Task 3: CLI と plugin を同じ input から導入する

**Files:**

- Modify: `nix/nix-darwin/home-manager/packages/work.nix`

- [ ] `inputs.cclens.packages.${system}.default` を work profile の package list に追加する。
- [ ] `pkgs.writeShellScriptBin` で `claude` wrapper を作る。
- [ ] wrapper は実体の `${pkgs.claude-code}/bin/claude` を次の引数付きで起動する。

  ```bash
  --plugin-dir ${inputs.cclens}/plugins/cclens
  ```

- [ ] wrapper は呼び出し元の引数を `"$@"` でそのまま渡す。
- [ ] package list の `pkgs.claude-code` を wrapper に置き換え、同名の `$out/bin/claude` が衝突しないようにする。
- [ ] `pkgs.awscli2` と Crit package は維持する。

CLI と plugin は同じ `inputs.cclens` の store path を参照する。
plugin は PATH 上の cclens を優先するため、Nix が導入した CLI を使う。
plugin 自体に hook はないので、Claude Code の既存 hooks は変更しない。

## 完了条件

- work profile に cclens CLI と Claude Code plugin が含まれる。
- CLI と plugin は同じ `inputs.cclens` revision を使う。
- `just us` 以外の専用更新コマンドを必要としない。
- `config/claude/settings.json` と Claude plugin marketplace に cclens の別 revision を持たない。
- cclens の DB が dotfiles の作業ツリー内に生成されない。
- unrelated な既存変更と `nix/local.nix` に触れていない。
